Приложение комментариев

Веб-приложение для работы с комментариями и ответами на них. Поддерживает вложенные обсуждения, загрузку файлов, сортировку, пагинацию и обновление данных в реальном времени.

Backend реализован на Laravel и предоставляет REST API. Frontend построен на React и TypeScript. Для хранения данных используется MySQL, для кеширования и очередей — Redis.

Архитектура

Приложение разделено на клиентскую и серверную части.

Frontend отвечает за отображение комментариев, формы создания комментариев и ответов, загрузку файлов, сортировку, пагинацию и получение обновлений в реальном времени.

Backend реализует REST API, проверку входных данных, бизнес-логику, сохранение комментариев и вложений, кеширование, фоновые задачи и отправку событий.

MySQL хранит основные данные приложения.

Redis используется для кеширования и обработки очередей.

Laravel Reverb обеспечивает передачу событий через WebSocket.

Nginx принимает HTTP-запросы и направляет их к соответствующим сервисам.

Сервисы приложения запускаются в отдельных контейнерах Docker.

Требования

Для запуска приложения необходимы:

* Git
* Docker Engine
* Docker Compose v2

Устанавливать PHP, MySQL и Redis непосредственно на хостовую систему не требуется, если приложение запускается через Docker Compose.

Установка и запуск

1. Клонирование репозитория

git clone <АДРЕС_РЕПОЗИТОРИЯ>
cd comments-app

Вместо <АДРЕС_РЕПОЗИТОРИЯ> укажите адрес Git-репозитория.

2. Создание файлов окружения

Создайте корневой файл окружения:

cp .env.example .env

Создайте файл окружения Laravel:

cp backend/.env.example backend/.env

Если frontend использует отдельный файл окружения, создайте его на основе frontend/.env.example.

Убедитесь, что указанные файлы действительно присутствуют в репозитории. При необходимости скорректируйте команды под фактическую структуру проекта.

3. Настройка базы данных

В корневом .env укажите параметры MySQL, используемые Docker Compose:

MYSQL_DATABASE=comments
MYSQL_USER=comments
MYSQL_PASSWORD=<ПАРОЛЬ_ПОЛЬЗОВАТЕЛЯ>
MYSQL_ROOT_PASSWORD=<ПАРОЛЬ_ROOT>

В backend/.env настройте подключение Laravel:

DB_CONNECTION=mysql
DB_HOST=mysql
DB_PORT=3306
DB_DATABASE=comments
DB_USERNAME=comments
DB_PASSWORD=<ПАРОЛЬ_ПОЛЬЗОВАТЕЛЯ>

Пароль приложения должен совпадать с паролем пользователя MySQL, заданным при инициализации базы данных.

Внутри Docker Compose Laravel подключается к MySQL по имени сервиса mysql.

4. Настройка Laravel

В backend/.env укажите необходимые параметры приложения:

APP_ENV=production
APP_DEBUG=false
SESSION_DRIVER=database
QUEUE_CONNECTION=redis
CACHE_STORE=redis
REDIS_HOST=redis
REDIS_PORT=6379
BROADCAST_CONNECTION=reverb

Если ключ приложения ещё не создан, выполните:

docker compose run --rm backend php artisan key:generate

Не генерируйте новый ключ повторно для уже работающего приложения, если с текущим ключом зашифрованы данные.

5. Запуск контейнеров

Из корневого каталога проекта выполните:

docker compose up -d --build

Проверьте состояние контейнеров:

docker compose ps

Выполните миграции базы данных:

docker compose exec backend php artisan migrate --force

Сгенерируйте документацию API:

docker compose exec backend php artisan l5-swagger:generate

При необходимости очистите кеш Laravel:

docker compose exec backend php artisan optimize:clear

6. Проверка приложения

При текущей конфигурации с опубликованным портом 8081 приложение доступно по следующим адресам:

* Frontend: http://localhost:8081
* REST API: http://localhost:8081/api/v1
* Swagger UI: http://localhost:8081/api/documentation/
* Спецификация OpenAPI: http://localhost:8081/docs?api-docs.json

При локальном запуске адреса зависят от настроек Docker Compose. На сервере вместо localhost используется IP-адрес или доменное имя сервера.

Настройка окружения

Redis

Redis используется для кеширования и обработки очередей Laravel.

Основные параметры подключения:

CACHE_STORE=redis
QUEUE_CONNECTION=redis
REDIS_HOST=redis
REDIS_PORT=6379

WebSocket

Для передачи событий в реальном времени используется Laravel Reverb.

Backend и WebSocket-сервер должны использовать согласованные настройки подключения. Frontend подключается к опубликованному адресу и порту Reverb.

После изменения переменных окружения VITE_* необходимо пересобрать frontend:

docker compose up -d --build frontend

Google reCAPTCHA v3

Для интеграции необходимо создать проект в административной панели Google reCAPTCHA и получить ключ сайта и секретный ключ.

Ключ сайта используется на frontend. Секретный ключ должен храниться исключительно на backend.

Пример переменных окружения:

VITE_RECAPTCHA_SITE_KEY=<КЛЮЧ_САЙТА>
RECAPTCHA_SECRET_KEY=<СЕКРЕТНЫЙ_КЛЮЧ>

Названия переменных необходимо согласовать с реализацией приложения.

Предполагаемый процесс проверки:

1. Frontend получает токен reCAPTCHA для отправки комментария.
2. Токен передаётся вместе с запросом к API.
3. Backend отправляет токен на проверку Google.
4. Backend проверяет результат, действие и оценку риска.
5. Запрос принимается или отклоняется согласно результату проверки.

Секретный ключ нельзя помещать в клиентскую сборку или коммитить в репозиторий.

Документация API

REST API использует префикс /api/v1.

Swagger UI предоставляет интерактивную документацию с описанием доступных эндпоинтов, параметров запросов и схем ответов.

Интерфейс документации:

/api/documentation/

Спецификация OpenAPI в формате JSON:

/docs?api-docs.json

Для повторной генерации документации выполните:

docker compose exec backend php artisan l5-swagger:generate

Структура базы данных

MySQL используется для хранения комментариев, вложений и других данных приложения.

Основные таблицы:

* reviews — комментарии и ответы;
* review_attachments — метаданные вложений.

Ответы связываются с родительскими комментариями через поле parent_id.

Дополнительные таблицы используются Laravel для работы с пользователями, сессиями, кешированием, очередями и миграциями в соответствии с конфигурацией приложения.

Структура базы данных определяется миграциями Laravel.

Развёртывание

Для развёртывания на сервере:

1. Установите Docker и Docker Compose.
2. Клонируйте репозиторий.
3. Создайте и настройте файлы окружения.
4. Укажите пароли и секретные ключи.
5. Проверьте конфигурацию Nginx и опубликованные порты.
6. Соберите и запустите контейнеры.
7. Выполните миграции.
8. Сгенерируйте документацию API.
9. Проверьте работу frontend, API, загрузки файлов, очередей и WebSocket.

Основная команда запуска:

docker compose up -d --build

Проверка состояния сервисов:

docker compose ps

Просмотр логов:

docker compose logs --tail=100

Для пересборки frontend после изменения исходного кода:

docker compose up -d --build frontend
